# Проверка MathMCP на задачах матанализа

В [корпусе](mathmcp.json) 20 задач. Условия сформулированы как сообщения
студента. Эталон для каждой задачи описывает математический ответ и, где
нужен график, его область и особенности. В сквозном прогоне модель получает
только условие, обычные инструкции бота и схемы обнаруженных инструментов.

Прямой прогон использует тот же MCP-клиент и проверку схем, что и бот.
Клиент проверяет структурированный ответ, размер и целостность PNG.
Сквозной прогон добавляет OpenCode Go, учебный режим и агентный цикл.
Для каждого запроса сохраняются вызовы и аргументы, структурированные
результаты, время шагов, открытый ответ модели и PNG. Корректность
открытого ответа сверяется с эталоном вручную. Успех на задаче с графиком
требует PNG именно запрошенного типа и математически верной интерпретации.

## Воспроизведение

```bash
uv run --locked python -m scripts.run_mathmcp_eval --output /tmp/plan10-direct
uv run --locked python -m scripts.run_mathmcp_eval --live --output /tmp/plan10-opencode
```

Для второго запуска требуется настроенный профиль OpenCode Go с моделью
`deepseek-v4.1-flash` и `LLM_OPENCODE_SESSION=1`. По умолчанию прогоны
используют окно 131 072 и предел 32 768 токенов генерации на шаг.
Параметры `--case`, `--window` и `--output-tokens` позволяют
повторить отдельный запрос или проверить другой бюджет.

Для контрольного прогона с полным каталогом добавить `--full-catalog`.
Для него нужен локальный PostgreSQL. Учебные инструменты и ресурсы
показываются модели через discovery. Если модель выберет инструмент
вне MathMCP, прогон зафиксирует ошибку маршрутизации. Результаты
и PNG собираются локально через обычный агентный цикл.

## Исходный прогон

Измерение выполнено на коде MathMCP из плана 08 с бюджетом вызовов
из плана 09. Прогон охватил все 20 условий. За 35 шагов модели
выполнено 26 MCP-вызовов. 14 запросов дошли до ответа после выполнения
инструмента. Медианное время ответа составило 10,1 с.

Старый каталог содержал `math_calculate`, `math_solve` и `math_plot`.
Из девяти задач, для которых на старых схемах были заданы прямые вызовы,
семь прошли. Два несовпадения получены на несобственных интегралах.
В первом точное значение было записано через функцию Мейера G. Во втором
бесконечный результат возвращался без признака расходимости.
Модель не построила комплексные цветовые карты, а для нескольких
запросов на 3D отправила плоские сечения или исходный код.

## Проверка тайм-аутов и окружения

Оставлен общий тайм-аут запроса 240 с. Для обычного MCP действует 10 с,
для MathMCP — 40 с. В MathMCP по умолчанию доступны 5 с ожидания
исполнителя, 30 с запуска процесса и 5 с вычисления. Прогрев короткого
графика переносит подготовку SymPy и Matplotlib до первого запроса.
Коды ожидания очереди, старта вычислителя и истечения дедлайна проверяются
отдельно. Размер PNG настраивается до 256 КиБ.

В контейнере без доступа наружу холодный запуск MathMCP по stdio вместе
с discovery занял 7,48 с, следующий complex-height PNG — 258 мс.
По Streamable HTTP прогрев занял 4,00 с, discovery готового сервера —
206 мс, вызов графика — 290 мс. Размер одного и того же PNG в двух
транспортах составил 143 793 байта. Для этой проверки использован локальный
образ с теми же версиями Python-зависимостей и смонтированный рабочий код.
Отдельно проверены обычная конфигурация Compose и подключение двух TOML-профилей.

В контекстном регрессионном сценарии обязательная часть оставляет те же
237 токенов, что и в исходном инциденте. Тест ждёт `context_budget` до
первого обращения к LLM. Для Go целевой резерв составляет 4 096 токенов.
Для малых окон действует верхняя граница в одну восьмую окна. Тесты
проверяют также сохранение результатов инструментов при удалении старых
пар и компактизацию, когда порог по числу сообщений ещё не достигнут.

## Структура MathMCP

- [server.py](../../../mcp_servers/math_tools/server.py) публикует три
  инструмента FastMCP. В описаниях discovery указаны допустимые аргументы,
  точные границы, поддерживаемые типы графика и примеры вызовов.
- [schemas.py](../../../mcp_servers/math_tools/schemas.py) описывает
  структурированные результаты, включая сходимость, матрицы, экстремумы,
  контрольные точки, разрезы и реально нанесённые маркеры нулей.
- [service.py](../../../mcp_servers/math_tools/service.py) проверяет параметры
  и допустимые переменные, передаёт JSON-задачу вычислителю и проверяет
  размер и сигнатуру PNG перед возвратом в MCP.
- [runtime.py](../../../mcp_servers/math_tools/runtime.py) управляет одним
  изолированным процессом, очередью, прогревом и дедлайнами.
  [worker.py](../../../mcp_servers/math_tools/worker.py) применяет лимит
  памяти и передаёт запрос в вычислитель.
- [syntax.py](../../../mcp_servers/math_tools/syntax.py) и
  [expressions.py](../../../mcp_servers/math_tools/expressions.py) задают
  разрешённый AST и ограничения области исходного выражения.
  [engine.py](../../../mcp_servers/math_tools/engine.py) выполняет
  символьное вычисление и проверяет точность и статус.
  [plotting.py](../../../mcp_servers/math_tools/plotting.py) формирует сетки,
  маски, подписи и PNG через Matplotlib.

Условные экстремумы поддерживают одно уравнение-ограничение и две или три
переменные. Метки минимума и максимума сравнивают найденных кандидатов.
Глобальность требует обосновать компактность, регулярность ограничения
и полноту набора точек. Для незавершённых символьных вычислений выдаётся
диагностика, а распознавание численного приближения само по себе не считается
доказательством точной формулы.

| [context_builder.py](../../../app/services/context_builder.py) | Сравнивает обязательную часть и историю с бюджетом, пытается сделать одну сводку. Сохраняет пары реплик в запросе или исключает их целиком. |
| [dialog_service.py](../../../app/services/dialog_service.py), [agent_service.py](../../../app/services/agent_service.py) и [execution.py](../../../app/core/schemas/execution.py) | Передают дедлайн и границу обязательного контекста. | [tool_execution.py](../../../app/services/tool_execution.py) и [tools.py](../../../app/core/schemas/tools.py) | Ограничивают MCP оставшимся временем запроса и выводят различимые коды очереди, холодного старта и вычислительного тайм-аута. |
| [app/mcp/connection.py](../../../app/mcp/connection.py) | Задаёт отдельное ожидание MathMCP в 40 с и передаёт разрешённый набор настроек в stdio. |
| [app/modes/definitions.py](../../../app/modes/definitions.py) | Учебный промпт использует математические инструменты для проверки результатов и строит запрошенный тип графика через discovery. Каталог MCP остаётся общим для всех ролей. |
| [app/handlers/dialog.py](../../../app/handlers/dialog.py) | Измеряет отправку PNG по числу вложений, ошибок и миллисекунд. |

Полный локальный прогон использовал значимые значения действующего профиля
OpenCode Go. Для сравнения в обоих корпусах зафиксированы окно 131 072 и
потолок генерации 32 768. У локального `.env` были увеличены дедлайны LLM
до 600 с и агента до 900 с. Базовые значения проекта остаются 180 и 240 с.

Построчное сравнение бота с состоянием до плана 10 сохранено в
[bot.patch](bot.patch). Сравнение учитывает изменения плана 09, которые
уже были в рабочей копии.

## Итоговая приёмка

Все 19 задач с прямыми эталонами прошли через MCP. Двадцатый случай
проверяет запрос уточнения без MCP. В сквозной проверке выполнены все
20 запрошенных результатов, включая восемь PNG. В 19 из 20 случаев
последовательность вызовов соответствует задаче. В одном случае модель
верно нашла предел, но дополнительно попыталась просуммировать числовой ряд
при разборе формулы Тейлора. Медиана итоговых ответов составила 10,26 с,
самый долгий из отобранных прогонов занял 17,62 с.

Общий запуск `RUN_INTEGRATION=1 uv run --locked pytest -q` дал 737 успешных
проверок, включая 19 сценариев с PostgreSQL. Проверки `ty`, Ruff и
форматирования тоже прошли. Сквозные проверки Telegram используют моки.
Контейнерная проверка подтверждает запуск на локальном образе. Для новой
сборки с нуля потребуются базовые образы Python и uv, отсутствовавшие
в локальном Docker.

С полным каталогом бота дополнительно проверены `1/z`, `log(z)`, 3D-поверхность
`|z²−1|` и задача на критические точки с графиком. Все четыре сценария
вернули PNG нужного типа. В задаче на критические точки модель вызвала
производную, решение уравнения и график. В другой попытке та же задача
заняла весь лимит из пяти вызовов, поэтому ошибки выбора и избыточные
вызовы отражены в отчёте отдельно.

Во время проверки уточнены описание второй частной производной, синтаксис
ограничения для экстремумов и сведения о метках нулей. После уточнения
модель передала `order=2` и `variable="x"`, использовала исходное уравнение
окружности и правильно описала оба отмеченных нуля. Эксперимент с отдельным
`math_derivative` дал выбор существующего `math_calculate(diff)` на том же
условии, поэтому в каталоге оставлены три прежних имени. Итоговые числа
учитывают повторные проверки после исправлений. Модель иногда добавляет
неточные детали к правильному основному решению. Эти наблюдения сохранены
по отдельным задачам.
