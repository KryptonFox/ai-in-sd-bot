# Дополнительный набор маршрутизации Lab 3

[`lab3-routing-supplemental.json`](lab3-routing-supplemental.json) дополняет
официальные [15 запросов](lab3-routing.json). Официальный набор не изменяется:
его состав и `sha256` проверяются оценщиком. Дополнительные случаи разделены
на два самостоятельных набора:

- `math` — 8 запросов на вычисления, проверку, решение, график и продолжение
  математической задачи;
- `web` — 7 запросов к веб-источникам и сравнений лекции с веб-материалом.
  Маршрут для них — `knowledge`, как требует план Lab 3.

Пограничные случаи помечены `boundary: true`. В наборе Math это проверка
утверждения из конспекта вычислением: источник задаёт контекст, но действие
остаётся математическим. В наборе Web сравнение конспекта с веб-источником
относится к Knowledge. Для продолжений сохранена короткая история; у согласия
на ранее предложенный поиск есть метаданные `web_search_offer`.

## Оценка

Запуск выполняется только через
[`scripts/run_lab3_routing_eval.py`](../../scripts/run_lab3_routing_eval.py).
Один случай — один вызов `DecisionsRouter.route`. Официальный набор, Math и Web
считаются отдельно; каждый выбранный случай входит в знаменатель своего набора,
включая ошибки провайдера, тайм-ауты и пустые ответы. Неуспешные запросы
не удаляются из знаменателя.

```bash
uv run --locked python -m scripts.run_lab3_routing_eval \
  --mock-scenario success --output-dir /tmp/lab3-routing-mock
uv run --locked python -m scripts.run_lab3_routing_eval \
  --mock-scenario faults --output-dir /tmp/lab3-routing-faults
uv run --locked python -m scripts.run_lab3_routing_eval \
  --live --output-dir /tmp/lab3-routing-live
```

Без `--live` сетевых вызовов нет. Сценарий `faults` подставляет ошибку и
неверные маршруты, чтобы проверить знаменатель и сериализацию ошибок.
Сквозная проверка специалистов и `DialogService` в этот оценщик не входит:
её следует брать из отдельной интеграционной проверки, чтобы не выдавать
маршрутное решение за выполненный сценарий.

`DecisionsRouter` записывает `input_tokens` и `output_tokens` из метаданных
провайдера во вложенный этап трассы `router/api_request`. Оценщик читает эти
необязательные счётчики; если данных нет, в JSON остаётся `null`.
`opencode.allowance` — исторический показатель счёта, а не доказанный расход
конкретного запроса. Оценщик не делает дополнительных запросов к биллингу
и не выдаёт отсутствие данных за нулевой расход квоты.

Человекочитаемый JSON содержит режим, модель, хеши наборов, решение, целевую
метку, `confidence`, время вызова, ошибку без текста провайдера и отдельные
итоги для Math и Web.
