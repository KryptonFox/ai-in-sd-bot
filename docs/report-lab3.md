# Отчёт по лабораторной работе № 3

**Тема:** специалисты, расписание и уведомления в Telegram-агенте

**Статус:** рабочая версия. Оценщик, дополнительный набор Math/Web, конституция
и документация подготовлены. Живой прогон OpenCode в этом изменении не
выполнялся; результаты остальных проверок зафиксированы ниже.

В маршрутизируемом режиме специалист `legacy` не получает MCP tools и
resources: общие запросы и перевод обслуживаются инструкциями без новых прав.
Если ключ Router не настроен, Supervisor не создаётся и приложение использует
прежний Lab 2 fallback-агент с отдельным каталогом `get_weather`, `get_schedule`,
`get_schedule_week`, `add_reminder`, `math_calculate`, `math_solve`, `math_plot`
и `schedule://current-week`; учебный корпус и веб-поиск в этот каталог не входят.
Напоминание доставляется по подтверждённому напоминанию и сохранённому личному
чату. Сводка `daily_briefing` дополнительно требует согласия, подтверждённого
города и IANA-зоны.

## Что проверяет оценщик

[`scripts/run_lab3_routing_eval.py`](../scripts/run_lab3_routing_eval.py)
выполняет один вызов `app.llm.decisions.DecisionsRouter.route` на один
синтетический запрос. Официальные [15 запросов](evaluation/lab3-routing.json)
не изменены: оценщик проверяет их количество, уникальность ID и `sha256`
`3a1e058d8f5c467eb84ac775f886b148b14a74c326015ebda9d175e26fb39236`.
Дополнительный [набор](evaluation/lab3-routing-supplemental.json) содержит
8 случаев Math и 7 случаев Web; они считаются отдельно от официального набора.
Math проверяет вычисления, решение, график, продолжение задачи и пограничный
случай с проверкой утверждения из конспекта. Web проверяет явный поиск,
сравнение с лекцией, продолжение после предложенного поиска и пограничные
случаи между учебным корпусом и веб-источником.

Каждый выбранный случай остаётся в знаменателе своего набора, включая
тайм-аут, отказ, ошибку провайдера и пустой ответ. Официальный знаменатель —
15 случаев; Math — 8; Web — 7. Ошибки не удаляются и не заменяются успешными
повторами. Неверный маршрут также считается ошибкой.

Без `--live` оценщик использует детерминированные фикстуры и не делает сетевых
вызовов. Сценарий `faults` подставляет один тайм-аут, одну ошибку лимита и два
неверных маршрута, чтобы проверить знаменатель и сериализацию ошибок. Живой
режим включается только явным `--live` и требует настроенного Router.

## Метаданные расхода

`DecisionsRouter` выполняет Decisions-запрос внутри вложенного этапа трассы
`router/api_request`. Когда провайдер вернул `usage`, приложение записывает в
этот этап `input_tokens` и `output_tokens` из типизированного ответа SDK.
Родительский этап `router/choice`, который создаёт `DialogService`, остаётся без
счётчиков. Оценщик связывает локальную `OperationTrace` с каждым вызовом и
переносит необязательные счётчики в `usage` отчёта; при отсутствии данных
остаётся `null`, без оценки по тексту.

`opencode.allowance` не приписывается конкретному запросу: это исторический
показатель счёта, а не доказанный расход одного вызова. Оценщик не делает
дополнительных запросов к биллингу и не выдаёт отсутствие метрики за ноль.
Живой прогон не выполнялся, поэтому новых фактических токенов и квоты в этом
отчёте нет.

## Остаточный риск повторной доставки

Telegram Bot API не предоставляет универсального ключа идемпотентности для
`sendMessage`. Приложение фиксирует попытку до внешнего вызова и состояние
`sent` после него, поэтому сбой между успешной отправкой и записью результата
может привести к повторному сообщению. Уникальный ключ задания, аренда и
ограничение попыток снижают риск повторной подготовки и параллельной отправки,
но не устраняют неопределённость на границе Telegram.

Изменения подготовлены с использованием AI-ассистентов OpenCode. Сгенерированные

## Риски

- Маршрутный прогон не проверяет качество ответа и побочные действия.
- Дополнительные метки Math/Web редакторские; малая выборка не даёт широкой
  оценки модели.
- Исторический baseline получен другим harness и не заменяет живой прогон.
- Без авторизованного `--live` фактические токены и квота остаются неизвестными;
  счётчики появляются только из метаданных провайдера.
