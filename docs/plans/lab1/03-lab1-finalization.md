# План финализации Лабораторной работы № 1: эксперименты, отчёт и сдача

## Контекст и статус проекта

Все программные требования Лабораторной работы № 1 полностью реализованы и протестированы:
- **Архитектура**: Pydantic v2 схемы, чистая слоистая структура (`app/handlers`, `app/services`, `app/modes`, `app/llm`, `app/db`), сквозной `request_id` (correlation ID) и доменные исключения.
- **База данных**: миграции с `pg_advisory_lock` и SHA-256 контролем (`schema_migrations`, `user_settings`, `dialog_messages`), задел под Лабораторные 2 и 3 (`role IN ('user', 'assistant', 'system', 'tool')`, `metadata JSONB`).
- **Режимы**: `/study` (ментор по программированию), `/translate` (технический переводчик), `/review` (код-ревью со структурированным few-shot примером) через расширяемый реестр `ModeRegistry`.
- **Тесты**: 60 тестов (59 unit/scenario passed, 1 skipped для Docker integration), 100% прохождение всех 8 обязательных сценариев, Ruff check и format чистые.

---

## Согласованные решения (по итогам /grill-me)

1. **LLM Модель**: `nvidia/nemotron-3-ultra-550b-a55b:free` (OpenRouter, бесплатная текстовая модель с поддержкой `temperature` и системных инструкций без HTTP 402).
2. **Экспериментальный запрос (12 запусков)**:
   - Режим: `/study`.
   - Запрос: *«Объясни разницу между процессами и потоками в ОС, и в каких случаях в Python использовать multiprocessing вместо threading»*.
   - Сетка температур: `0.0`, `0.3`, `0.7`, `1.0` по 3 независимых повтора с предварительным `/reset`.
3. **Сравнение промптов**:
   - Базовый «голый» промпт: *«Ты помощник по программированию. Отвечай на вопросы пользователя.»*
   - Улучшенный промпт (R.C.T.F.): системный промпт режима `/study` (Role: ментор, Context: студент ИТМО, Task: объяснение + код + вопрос на самопроверку, Format: структура с заголовками, лаконичный код).
4. **Известное ограничение (Раздел 8 отчёта)**:
   - Эвристическая оценка объёма истории (символы / 3) без локального токенизатора модели + отправка сообщений >4096 символов без `parse_mode=MarkdownV2` во избежание синтаксических ошибок незакрытых тегов при разрезании текста.
5. **Декларация использования AI (Раздел 9 отчёта)**:
   - Исправление коллизии Python-пакета (`app/db.py` конфликтовал с директорией `app/db/migrations/`), исправление мока сессии aiogram (`MagicMock` $\to$ `AsyncMock`), диагностика HTTP 402 и переключение на бесплатную модель Nemotron.

## Этапы выполнения

### Этап 1. Подготовка окружения и запуск скрипта экспериментов
- Проверить `.env` на наличие `LLM_MODEL=nvidia/nemotron-3-ultra-550b-a55b:free`.
- Разработать скрипт `scripts/run_lab1_experiment.py`:
  - 12 запросов (4 температуры $\times$ 3 повтора).
  - Сброс контекста (`/reset`) перед каждым запросом.
  - Измерение времени ответа, длины (символы), токенов (`prompt_tokens`, `completion_tokens`, `total_tokens`), соответствия формату и ключевых наблюдений.
  - Выполнение 2 запросов для сравнения «голого» промпта и промпта R.C.T.F.
  - Сохранение сырых результатов в `scripts/experiment_results.json` и генерация Markdown-таблицы.
- Запустить скрипт и получить экспериментальные данные.

### Этап 2. Составление итогового отчёта (`docs/report-lab1.md`)
- Написать структурированный отчёт по 10 пунктам методички:
  1. *Цель работы и выбранный провайдер модели*.
  2. *Краткая схема прохождения сообщения через приложение* (с Mermaid-диаграммой).
  3. *Описание хранения и ограничения контекста* (БД, лимиты `MAX_HISTORY_MESSAGES`, `MAX_HISTORY_TOKENS`, алгоритм усечения).
  4. *Тексты трёх системных инструкций и разбор их ключевых элементов* (`/study`, `/translate`, `/review` с few-shot).
  5. *Таблица 12 экспериментальных запусков и вывод о влиянии `temperature`*.
  6. *Сравнение исходной и улучшенной инструкции* (таблица сравнения по критериям).
  7. *Перечень автоматических тестов и результат их выполнения* (сводка по 60 тестам).
  8. *Описание известного ограничения или нерешённого пограничного случая*.
  9. *Декларация использования AI-инструментов*.
  10. *Ссылка на репозиторий и тег `lab1`*.

### Этап 3. Сохранение истории планов и версионирование
- Скопировать утверждённый план в `docs/plans/lab1/03-lab1-finalization.md`.
- Обновить реестр планов в `docs/plans/README.md`.

### Этап 4. Контрольная валидация и создание Git-тега
- Запустить полный набор тестов: `uv run pytest -q`.
- Запустить линтер и форматирование: `uv run ruff check .` и `uv run ruff format --check .`.
- Проверить отсутствие секретов в `git status` и `git diff`.
- Зафиксировать коммит со всеми файлами Лабораторной работы № 1.
- Создать аннотированный тег: `git tag -a lab1 -m "Лабораторная работа № 1"`.
