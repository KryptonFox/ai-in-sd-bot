# План 07: упрощение после Lab 2

Статус: выполнен 2026-11-03.

Эта редакция следует за выполненным планом [06](06-agent-reliability-and-weather.md).
Она сохраняет его гарантии и сокращает собственные механизмы агента там, где
достаточно штатных контрактов MCP и существующих сервисов.

## Цели

- Использовать `FastMCP` 4.1.5 и SDK клиента для штатного discovery и вызова
  tools/resources на stdio и Streamable HTTP.
- Вынести demo-сервер погоды и расписания в `mcp_servers/student_tools`.
- Упростить агентный цикл, сохранив память, ограничения, подтверждения и recovery.

## Изменения

1. Сервер предоставляет функции через нативные MCP tools и расписание как resource.
   Клиент обнаруживает схемы динамически.
2. В обычный tool-calling request вместе с обнаруженными MCP tools включается
   локальная host-функция `read_resource(uri)` с URI enum из `list_resources`.
   Хост перехватывает этот function call, читает discovery resource через
   FastMCP Client и возвращает ответ с исходным `tool_call_id`. Серверный ресурс
   не появляется в `tools/list`; локальная функция не отправляется как
   `tools/call`.
3. `clarification(question)` становится локальным tool вместо `finish_response`.
   Продолжение задаётся только явным `StepAction.CONTINUE`, не значением `None`.
4. Удаляются `dry_run`, `planned` и собственные команды очереди транспорта.
   Напоминание нормализует только `ConfirmationService`; executor не читает часы.
5. Единственное предложение занимает стабильную позицию `0`; совместимость
   существующих подтверждений сохраняется.
6. Каталог tools динамический; свойства чтения берутся из discovery.
   Политика известных мутаций единая и централизована.
   Tool и resource reads идут через один обычный цикл LLM, разделяют лимит
   MCP-вызовов, а ошибка resource read возвращается модели как tool error
   content без автоматического повтора хостом.
7. Переносится demo MCP server в `mcp_servers/student_tools`, пакет
   `mcp_servers.student_tools`, CLI `python -m mcp_servers.student_tools`,
   Compose-сервис `student-tools-mcp`. Сохраняются внешние `SCHEDULE_PATH` и
   `.local`; локальные конфиги со старым default пути могут быть мигрированы.
8. LLM-клиент отвечает за SDK-вызов и диагностику; преобразование сообщений
   вынесено в `llm/codec.py`. Для обычного ответа используется строгая проверка
   SDK без повторной пересборки модели. MCP-каталог хранит definition,
   валидаторы и read-only признак одной записью на инструмент. Подключение
   выделено в `app/mcp/connection.py`, где создаётся FastMCP Client с нужным
   transport, auth и SDK timeout/init timeout. `MCPClient` получает готовый
   SDK-клиент, выполняет discovery и RPC внутри `async with` на каждую операцию;
   SDK reentrant references управляют общими сессиями. Для stdio `keep_alive=True`
   сохраняет процесс, HTTP использует SDK-сессии по операциям. `available` означает
   успешный discovery каталога, а не постоянно открытый сокет. RPC timeout не
   сбрасывает каталог и не прерывает соседние запросы; recovery повторяет
   discovery каждые 15 секунд только если каталог недоступен. Собственных lock/cooldown/retry для
   транспорта нет, отправленные RPC не переигрываются, а `Client.close()` вызывается
   только при shutdown. Сообщения известных ошибок tools задаются через defaults
   модели `ToolFailure`.
   `ToolExecutionService` отвечает за проверку batch, бюджет и политику
   исполнения; определения локальных функций принадлежат `AgentService`.
