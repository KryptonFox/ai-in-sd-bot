## Ключевые архитектурные решения

1. **Сервер FastMCP с гибридным транспортом:**
   * **SSE (Server-Sent Events)**: для работы в `docker compose` отдельным микросервисом `mcp-server:8000`.
   * **STDIO**: для запуска в `pytest` и независимой валидации через `npx @modelcontextprotocol/inspector`.

2. **Примитивы MCP:**
   * `get_weather(city: str)` — погодные данные и геокодирование через Open-Meteo, обработка неоднозначности городов.
   * `get_schedule(date: str)` — расписание занятий на дату `YYYY-MM-DD` из анонимизированного `schedule.json`.
   * `add_reminder(text: str, remind_at: str)` — создание напоминания после обязательного подтверждения пользователем. Доверенный `user_id` передаётся через транспортный контекст/метаданные, а не через аргументы модели.
   * `schedule://current-week` — ресурс с расписанием на текущую календарную неделю в заданной IANA-таймзоне с корректной обработкой стыковки месяцев и годов.

3. **Human-in-the-Loop и идемпотентность:**
   * Двухфазная схема: модель подготавливает вызов $\rightarrow$ сохранение в `pending_confirmations` (TTL 5 минут) $\rightarrow$ inline-кнопки пользователю.
   * Вызов инструмента мутации происходит строго после нажатия «Подтвердить».
   * Ключ идемпотентности (`idempotency_key`) защищает от дублирования при повторной доставке Telegram Update и двойных кликах.

4. **Агентный цикл (Agent Loop):**
   * Модель получает схемы инструментов через OpenAI Function Calling.
   * Guardrail: не более 2 MCP-вызовов на одно входящее сообщение.
   * Защита от Indirect Prompt Injection (результат инструмента изолирован в роли `tool`).

5. **Новые команды:**
   * `/tools` — динамический список инструментов от MCP-сервера с пометками `чтение` / `изменение`.
   * `/timezone <зона>` — настройка IANA часового пояса (`Europe/Moscow`) с валидацией через `zoneinfo`.
   * `/why` — отображение последнего решения из `decision_audits`.
