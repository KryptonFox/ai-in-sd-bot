# План 08. Независимый MCP-сервер `math_tools`

Статус: выполнен 2026-11-17. Дополнение к Lab 2 после [плана 07](07-post-lab2-simplification.md).

## Подключение

- `mcp_servers/math_tools` содержит самостоятельный FastMCP-сервер `math-tools`.
  Локально бот запускает оба сервера отдельными stdio-процессами. В облаке бот
  обращается напрямую к двум сервисам, `student-tools-mcp` и `math-tools-mcp`,
  по Streamable HTTP. `math_tools` не зависит от `student_tools`, БД или Telegram.
- Использовать существующий `MCPClient` для каждого подключения. В `app/mcp`
  добавить небольшой составной `ToolClient`, который объединяет discovery
  доступных клиентов и делегирует вызовы, проверку аргументов и чтение ресурсов
  по имени инструмента или URI. Коллизии исключаются из общего каталога и
  отклоняются при прямом вызове. Каталоги и их валидаторы остаются у клиентов.
- При сборке приложения передать составной `ToolClient` в существующие
  `ToolExecutionService`, `DialogService` и health check. `ConfirmationService`
  получает непосредственно клиент `student_tools`. Запуск, повторный discovery
  недоступных серверов в текущем фоновом цикле и закрытие выполняются независимо.
  Агентный цикл, имена существующих инструментов и общий бюджет сохраняются.
- В HTTP-режиме `MATH_MCP_SERVER_URL` задаёт адрес второго сервера. Пустое
  значение сохраняет прежний режим с одним сервером. Compose задаёт внутренний
  адрес, запускает `math-tools-mcp` с проверкой `/health` и без публикации порта.
  Использовать существующий Bearer-секрет. Сбой одного MCP не блокирует другой.

## Математические инструменты

MathMCP сам публикует инструменты с префиксом `math_`, схемами и `readOnlyHint`.
Модель выбирает их по описаниям из discovery.

| Инструмент | Возможности |
| --- | --- |
| `math_calculate` | Упрощение, точное и численное вычисление, производные, определённые и неопределённые интегралы, пределы. Переменная по умолчанию `x`, численная точность 15 знаков. |
| `math_solve` | Уравнение или система до трёх уравнений с указанными неизвестными. Вещественные решения по умолчанию. Проверять решения по исходным уравнениям и области определения. |
| `math_plot` | От одной до четырёх функций `y=f(x)` на общих осях. Диапазон по умолчанию `[-10, 10]`. Описание кривых и диапазона возвращается как `structuredContent`, PNG как `ImageContent`. |

- Строить выражения SymPy из разрешённых узлов AST. Поддержать числа, переменные,
  скобки, явное умножение, `**` и `^`, базовые математические функции. Ограничить
  выражение 512 символами и 128 узлами. Вычисление пользовательского текста
  через `eval`, `sympify` и `parse_expr` исключено.
- Выполнять вычисления и рендеринг в отдельном процессе. Один активный расчёт
  на сервер, лимит 5 секунд на операцию и 768 МиБ памяти. При тайм-ауте и отмене
  завершать процесс и дожидаться выхода. Отдельно возвращать отсутствие решения,
  неопределённый результат и превышение лимита.
- Строить PNG в памяти через Matplotlib Agg, разрывать кривые на участках вне
  вещественной области и известных разрывах, включая полюс `1/x`.

## Фото в боте

- Расширить результат вызова `ToolClient` вариантом с фото для инструментов
  чтения. Проверять PNG и лимит 256 КиБ на изображение. Текстовые результаты
  сохраняют существующий формат. Обработка фото не зависит от имени инструмента.
- Передавать модели только структурированные текстовые данные. Переносить
  изображения отдельно через состояние агентного запуска в `AgentResult`.
  Отправлять форматированный ответ и затем фото через `BufferedInputFile`.
  При сбое отправки фото сообщать об этом текстом.
- Сохранять ограниченные изображения в существующем JSON результата события,
  чтобы повторная выдача сохраняла фото. Старые записи читаются с пустым списком
  изображений. История диалога и аудит остаются текстовыми, миграция БД не нужна.

## Результат выполнения

[Устройство итогового MCP](../../reports/plan08-mcp-structure.md) и
[построчный разбор изменений бота](../../reports/plan08-bot-lines.md).

- Реализован самостоятельный `math-tools`: три read-only инструмента, discovery
  входных и выходных схем, stdio и Streamable HTTP с Bearer-авторизацией и `/health`.
- Выражения строятся из разрешённого AST; десятичные литералы сохраняют исходную
  точность. Проверка решений сохраняет ограничения исходной области определения
  до упрощения, включая сокращающиеся знаменатели, корни и логарифмы.
- Вычислительный процесс ограничен 768 МиБ и пятью секундами на операцию;
  тайм-аут и отмена завершают процесс с ожиданием его выхода. Запросы сериализованы.
- Составной клиент объединяет доступные серверы, исключает коллизии имён и URI,
  независимо восстанавливает соединения. Подтверждения остаются у `student_tools`.
- PNG передаются отдельно от текста модели, сохраняются в JSON результата события
  и повторно выдаются в Telegram. Проверяются PNG-структура, CRC и пиксельные данные;
  лимиты — 256 КиБ на изображение и два изображения на результат.
- Обновлены Compose, облачная упаковка, README и пример переменных окружения.
  Дополнительно по запросу пользователя добавлен флаг `LLM_OPENCODE_SESSION`
  для тестирования API Go с собственным User-Agent и сессией на время жизни клиента.

Практические ограничения:

- Первичный импорт вычислительного процесса имеет отдельный тайм-аут запуска
  30 секунд; лимит пять секунд применяется к операции после готовности процесса.
- График использует сетку из 2001 точки и промежуточные проверки; разрывы или
  узкие участки области определения между отсчётами могут быть пропущены.
- Решатель требует перечислить все свободные символы как неизвестные;
  отдельные символические параметры не поддерживаются.
- Сессия OpenCode в тестовом режиме общая на экземпляр LLM-клиента;
  отдельная изоляция диалогов этим флагом не реализуется.
- Реальная LLM-проверка ограничена шестью синтетическими запросами; это не
  нагрузочная проверка и не гарантия всех режимов Go. Отправка сообщений Telegram
  и облачное развёртывание не выполнялись. Коммиты не создавались;
  изменения оставлены в рабочей копии.
