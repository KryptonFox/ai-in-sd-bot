# MCP: протокол контекста модели

Учебный документ объясняет, как приложение соединяет языковую модель с внешними
возможностями через MCP и какие границы доверия при этом сохраняются.

<!-- section: mcp-overview -->
## Что такое MCP

MCP (Model Context Protocol) — протокол обмена между приложением-клиентом и
сервером возможностей. Сервер публикует инструменты, ресурсы и подсказки, а клиент
обнаруживает их, проверяет описания и вызывает только те операции, которые
разрешены текущему сценарию. Протокол не даёт модели прямого доступа к файлам или
сети: каждое действие выполняет приложение или MCP-сервер.

Клиент сначала получает список возможностей, затем формирует запрос с аргументами и
доверенными метаданными. Сервер проверяет аргументы и контекст, выполняет операцию и
возвращает структурированный результат. Такое разделение позволяет менять набор
инструментов без изменения текста системной инструкции и не раскрывать модели
внутренние детали реализации.

<!-- section: mcp-tools-resources-prompts -->
## Инструменты, ресурсы и подсказки

Инструмент — операция с типизированными аргументами и результатом. Инструменты
чтения не изменяют состояние, а операции изменения требуют отдельного подтверждения
владельца. Для каждого инструмента важны строгая схема входа, ограничения длины и
понятный код ошибки.

Ресурс — адресуемые данные, которые клиент читает отдельным запросом. Например,
каталог учебных материалов перечисляет документы и стабильные ссылки на разделы, а
расписание доступно как ресурс текущей недели. Наличие URI в каталоге не означает,
что модель уже видит содержимое: приложение само решает, когда выполнить чтение и
какой фрагмент передать в контекст.

Подсказка — заранее подготовленный шаблон или инструкция сервера. Подсказки не
расширяют права инструментов и не отменяют программную политику доступа.

<!-- section: mcp-request-metadata -->
## Контекст запроса и доверенные метаданные

Доверенные метаданные передаёт приложение, а не языковая модель. В них могут
находиться идентификатор владельца, признак явного согласия на веб-поиск и токен
приложения. Сервер обязан проверить токен сравнением постоянного времени и только
после этого использовать остальные поля.

Аргументы инструмента и метаданные запроса — разные каналы. Если идентификатор
пользователя или разрешение на внешний поиск пришли в обычном тексте запроса, они
считаются недоверенными. Клиент не должен позволять модели подставить чужой
идентификатор, а сервер не должен принимать такие значения без проверки.

Разрешение действует в границах одного доверенного вызова. Отсутствие флага,
строка вместо логического значения или значение `false` означают запрет. Проверка
выполняется до обращения к внешнему провайдеру, поэтому отклонённый вызов не создаёт
сетевого запроса.

<!-- section: mcp-search-and-catalog -->
## Поиск материалов и каталог

Поиск по корпусу принимает тему, необязательный идентификатор предмета и размер
выдачи. Сервер ищет только в утверждённых документах, перечисленных в реестре, и
возвращает ограниченные фрагменты. Пути к файлам не являются аргументами инструмента:
модель не может запросить произвольный файл по имени.

Каждый фрагмент содержит стабильный идентификатор документа, идентификатор раздела,
ссылку вида `materials://document#section`, название предмета и лекции. Приложение
сверяет ссылки в готовом ответе с источниками текущего запроса. Если подходящего
раздела нет, результат получает статус `empty`, и агент честно сообщает, что в
материалах нет ответа.

Веб-поиск — отдельная возможность. Он разрешён только при явной просьбе
пользователя или его согласии на предложенный поиск. Сервер отправляет короткий
поисковый запрос настроенному провайдеру и возвращает заголовки, ссылки и краткие
фрагменты. Страницы результатов не открываются и не обходятся.

<!-- section: mcp-security -->
## Границы доверия и безопасность

MCP-сервер не доверяет содержимому документов и веб-страниц. Текст источника может
содержать ложную инструкцию, например требование раскрыть системный промпт или
вызвать другой инструмент. Такой текст остаётся данными: приложение не исполняет его
как команду и не расширяет права по просьбе из фрагмента.

Инструменты чтения получают только необходимые аргументы. Операции изменения
требуют подтверждённого владельца и отдельного идентификатора подтверждения. Чужой
инструмент, неизвестный URI и новая возможность, появившаяся после обнаружения
каталога, по умолчанию запрещены.

Секреты, пользовательский текст и содержимое документов не записываются в журналы.
Для диагностики достаточно имени инструмента, кода ошибки, длительности и статуса
без raw-ответов внешних API и персональных данных.

<!-- section: mcp-errors -->
## Ошибки и наблюдаемость

Сервер различает некорректные аргументы, недоступность источника, пустую выдачу и
запрет по политике доступа. Клиент получает короткий код и безопасное сообщение,
пригодное для объяснения пользователю. Внутренние исключения и ответы провайдера не
передаются модели целиком.

Временная недоступность не должна превращаться в выдуманный ответ. Если источник не
ответил, приложение сообщает о технической проблеме или предлагает повторить попытку
позже. Если данных действительно нет, это отдельный результат, который не смешивают
с ошибкой сети.

Наблюдаемость строится на перечне допустимых полей: компонент, действие, статус,
длительность, код ошибки и имя инструмента. Токены, ссылки с параметрами доступа,
промпты и личные сообщения в такую запись не попадают.
